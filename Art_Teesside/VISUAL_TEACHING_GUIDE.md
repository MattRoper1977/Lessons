# Art Teesside visual-teaching layer

## Purpose

`art-teach.css` and `art-teach.js` are a progressive-enhancement layer for the existing Art Teesside teaching estate. They strengthen presentation, pacing, visual focus, interaction state, keyboard use, motion lifecycle, reduced-motion behaviour and projector/mobile resilience without becoming a second lesson system.

The authored HTML remains authoritative. Existing wording, punctuation, examples, artist references, health-and-safety guidance, assessment language, evidence requirements, links, sequence, timers, matching logic, reveal logic, print mirrors, branding and palette values are not edited by the shared layer.

## Scope

The layer is referenced by 35 entry points:

- 31 ten-slide lesson decks;
- `Art_Teesside/Build/START_HERE.html`;
- `Art_Teesside/Grow/START_HERE.html`;
- `Art_Teesside/Launch/START_HERE.html`;
- `art_teesside.html`.

Printable packs, schemes of work, run sheets and support records remain outside the presentation injection. They are still covered by the estate, reference and print instruments.

The exact current population is generated by:

```bash
python3 Art_Teesside/tools/inventory_estate.py --check
```

## Source of truth and generated references

Edit only:

- `Art_Teesside/art-teach.css`;
- `Art_Teesside/art-teach.js`.

Each applicable HTML file contains one small generated CSS reference block before `</head>` and one generated JavaScript reference block before `</body>`. Apply or refresh them with:

```bash
python3 Art_Teesside/tools/apply_visual_teaching.py --apply
```

Never hand-edit an `ART-TEACH` marker block. The injector is idempotent, refuses partial or duplicated markers, and verifies that removing its two exact additions reproduces the recorded authored bytes.

## Content-preservation contract

`Art_Teesside/tools/visual_content_baseline.json` records byte counts and SHA-256 hashes for every applicable authored file at source revision `10936b7f780f2fb18a8b3de9cd534b9e679cc305`, before the generated references were inserted.

This command strips only those exact generated blocks in memory and proves all 35 authored files round-trip byte for byte:

```bash
python3 Art_Teesside/tools/apply_visual_teaching.py
```

Do not regenerate or overwrite the baseline to make a changed lesson pass. A real curriculum change needs its own reviewed content decision and an explicit baseline update that explains why every changed byte is authorised.

## Behaviour added

The shared layer adds or strengthens:

- clear slide staging and current-teaching focus while retaining the existing identity and colour tokens;
- responsive navigation and classroom-sized touch targets;
- visible keyboard focus and interaction states that do not rely on colour alone;
- live progress for authored presentation-card and matching activities;
- a teacher-controlled card picker that selects without revealing or changing the authored score;
- completed matching trails that repeat only the exact existing card and target wording;
- authored diagram replay, short explanatory emphasis and paused inactive-slide animation;
- reduced-motion and print safeguards;
- neutral, hidden accessibility announcements;
- hub skip links, card labels and restrained entry hierarchy.

It does not alter answers, add examples, auto-advance lessons, replace authored functions or introduce curriculum claims.

## Runtime lifecycle

The JavaScript is idempotent. `data-art-teach-boot` prevents duplicate initialisation and `window.ArtTeach` exposes the maintained runtime namespace. Slide synchronisation reacts only to genuine authored state changes, batches work with `requestAnimationFrame`, and avoids observing its own presentation classes recursively.

Generated interface elements are removed from print. Content is never dependent on an animation finishing, and non-essential motion is disabled under `prefers-reduced-motion: reduce`.

## Validation

Run each gate separately and inspect its exit code before the next gated action:

```bash
python3 Art_Teesside/tools/inventory_estate.py --check
python3 Art_Teesside/tools/assert_visual_layer.py --self-test
python3 Art_Teesside/tools/assert_visual_layer.py
python3 Art_Teesside/tools/apply_visual_teaching.py
python3 Art_Teesside/tools/assert_kit.py --verbose
python3 Art_Teesside/tools/assert_instrument_contracts.py kit-current
python3 Art_Teesside/tools/assert_estate.py
python3 Art_Teesside/tools/assert_instrument_contracts.py estate-control
python3 Art_Teesside/tools/assert_cooccurrence.py
python3 Art_Teesside/tools/assert_instrument_contracts.py cooccurrence-current
python3 Art_Teesside/tools/assert_instrument_contracts.py cooccurrence-control
node Art_Teesside/tools/assert_print.js --verbose
python3 Art_Teesside/tools/assert_instrument_contracts.py print-control
node Art_Teesside/tools/assert_visual_browser.js --self-test
node Art_Teesside/tools/assert_visual_browser.js --base-url http://127.0.0.1:4173/Lessons/
```

The raw co-occurrence command currently exits 1 for two declared, pre-existing curriculum/kit contradictions. The contract wrapper requires that exact result so it cannot be mistaken for a clean zero and so any movement fails the release. The findings are not silently repaired by changing approved lesson wording.

The browser assertion runs every applicable page at 1920×1080, 1280×720, 768×1024 and 390×844, then exercises every lesson deck’s authored interaction types at 1280×720. The print assertion uses the established 718×1047px standard and verifies both sheet height and PDF page count.

## Adding or removing a page

1. Decide whether it is a renderable lesson/hub or a printable/support resource.
2. Update the explicit population contract in `apply_visual_teaching.py`, `assert_visual_layer.py`, `inventory_estate.py` and the browser assertion only when the classification is intentional.
3. For an applicable page, run the injector; never copy a marker block by hand.
4. Run the full static, instrument, browser, reduced-motion and print gates.
5. Update the content baseline only through a separately reviewed curriculum change.
6. Verify the deployed public bytes, content types, same-origin references and canonical route after merge.
