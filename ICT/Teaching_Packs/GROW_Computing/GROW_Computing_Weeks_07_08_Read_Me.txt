THE GROW CHASSIS — 40 MINUTES
Arrival 0–3 / Starter 3–6 / I Do 6–11 / We Do 11–18 /
I Do 2 18–21 / We Do 2 · Task 21–25 / Independent Task 25–35 / Exit 35–40.
Within Independent Task, use 25–32 for work and 32–35 for a demonstration and
pupil voice: “What I said, and what it changed”. Routes are flexible support
choices. Pointing, speech, an adult scribe and quiet individual sharing are welcome.
Record unfinished work and agree additional time when needed.

WEEK 7 — ADD ONE CHALLENGE
Start with the pupil’s own W06_Win.sb3. Save a copy as W07_Challenge.sb3.
The common task is one moving Hazard and a contact rule on Player. The slides
show both scripts. The model uses a 20-unit diamond Hazard at x 0, gliding
between y -100 and y 100 in 2 seconds each way. Player returns to (-180,-120).
For another maze choose clear endpoints and a safe start. Test a complete route.
Challenge compares 2-second and 4-second glides: slower is not always easier.
A collectible, scoring system or different mechanic needs its own complete
instructions and tests; agree additional teaching time before offering it.
The deliberate Week 7 bug puts the contact rule on Hazard, moving the wrong sprite.

WEEK 8 — TEST AND IMPROVE
Start with the pupil’s own W07_Challenge.sb3 and save as W08_Final.sb3.
Use the five-check record: four arrows; clear space and two walls; Finish;
Hazard journey, avoidance and contact; restart after a win.
Use a known setup and repeat it after a change. Record actual observations.
The shared bug project deliberately has down moving up, a wall check that runs
only at the flag, and an old win message that survives restart. The Finish and
Hazard checks pass. The complete teacher model has all three faults repaired.
A pupil’s own game may pass every check. Record that honestly. A useful playing
instruction, an edge case or an agreed next step can follow; do not invent a fault.

HTML AND SCRATCH
The HTML is a shared practice model, not a Scratch editor. Its arrows advance
time by 0.1 second and its time button by 0.5 second. Scratch glides continuously.
Position probes isolate a rule; pupils must also try a full playable route.
The shared check history stays in the downloaded response record. Record tests
of the pupil’s own Scratch file in the booklet; shared results do not replace them.
Download or print HTML responses before closing or reloading the page.
In Scratch use File > Load from your computer to open .sb3, and File > Save to
your computer to save. Reopen the pupil file to check the save. HTML needs no
external assets; the Scratch website needs internet, while the installed app
can open the included projects offline.
Recovery files contain inherited earlier work. Observe and record what the pupil
creates or tests; a completed teacher model cannot establish pupil authorship.
