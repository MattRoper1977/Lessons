Local controls are not GitHub firing experiments. Scratch RED/GREEN/DORMANT
branches will start from the landed repair, target main, and close unmerged:

- RED changes only one previously uncovered pinned JSON file, by whitespace;
  no checker/workflow change. The existing digest assertion must fail by name.
- GREEN makes the same file change and corrects exactly its pin in that same
  commit; no workflow change. The actual gate must pass.
- DORMANT adds an unrelated internal note; no pinned file or checker change.
  Record all runs for the exact SHA and an observation window, not an empty
  API response alone. Compare with the successful positive trigger controls.

Reason for ordering: a PR that also includes the workflow repair cannot prove
file-only causation. GitHub uses a three-dot diff for PR path filters and this
workflow targets main. A non-main scratch base or changing its branch filter
would test a different workflow. Repair CI and local controls therefore precede
merge; isolated GitHub controls follow it. No planted file or pin is merged.

Current GitHub path filtering has documented diff limits; exact generated
paths do not remove them. This pass proves small PRs, matching Matt's small-pass
workflow. The daily digest run remains for cross-repository drift.
[GitHub workflow path-filter and diff documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#git-diff-comparisons).
